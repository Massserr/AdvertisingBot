# AGENTS.MD

Инструкции для Codex/AI-агентов, работающих в этом репозитории.

## Проект

MVP-платформа для покупки и продажи рекламы в Telegram-каналах:

- Telegram Bot;
- Telegram Mini App;
- NestJS backend;
- PostgreSQL + Prisma;
- Redis + BullMQ;
- админ-панель;
- ЮKassa для пополнения баланса рекламодателя.

Автоматические выплаты владельцам каналов через ЮKassa не входят в MVP, но архитектура должна быть готова к их подключению без переработки финансового ядра.

## Структура

- `apps/api` - backend, Prisma-схема, бизнес-логика, платежи, очереди.
- `apps/bot` - Telegram Bot.
- `apps/mini-app` - Telegram Mini App.
- `apps/admin` - web admin panel.
- `packages/shared` - общие константы и типы.

## Ключевые архитектурные правила

1. Backend является источником истины.
2. Балансы нельзя менять без записи в `FinancialTransaction`.
3. Баланс не должен быть только одним числом в таблице пользователя.
4. Деньги рекламодателя проходят через доступный баланс и замороженный баланс.
5. Начисления владельцу и комиссия платформы создаются только после подтверждения публикации или автоподтверждения.
6. Выплаты всегда оформляются через `PayoutRequest`, даже ручные выплаты MVP.
7. Будущая автоматическая выплата через ЮKassa должна заменить только executor/provider выплаты, а не модель заказов, балансов и начислений.
8. Все webhook платежей должны быть идемпотентными и логироваться в `WebhookLog`.
9. Пользователь не должен иметь доступ к чужим каналам, заявкам, балансам и выплатам.
10. Действия администратора, влияющие на деньги, пользователей, каналы, споры или настройки, должны попадать в аудит.

## Работа с Prisma

- Главная схема: `apps/api/prisma/schema.prisma`.
- Начальные категории, форматы и настройки создаются в `apps/api/prisma/seed.ts`.
- При добавлении новых статусов или финансовых операций проверяйте все lifecycle-сервисы заказов, выплат и споров.

## Финансовое ядро

Все операции с деньгами должны проходить через сервисы домена финансов:

- `LedgerService` - заморозка, возврат, распределение суммы, ручные корректировки.
- `PaymentsService` - пополнение через ЮKassa и webhook.
- `PayoutsService` - заявки на вывод и подготовка к provider-based выплатам.

При добавлении новой операции:

- создайте запись в `FinancialTransaction`;
- обновите агрегированный баланс профиля в той же транзакции БД;
- добавьте связь с заказом, платежом или выплатой, если применимо;
- обеспечьте идемпотентность для внешних событий.

## Статусы заказов

Жизненный цикл заявки должен сохранять историю в `AdOrderStatusLog`.

Критичные переходы:

- создание заявки -> проверка баланса -> freeze;
- moderation on -> `awaiting_moderation`;
- moderation off -> `sent_to_owner`;
- decline/timeout/cancel -> refund/unfreeze;
- publish -> `awaiting_advertiser_confirmation`;
- confirm/autoconfirm -> owner reward + platform fee + `completed`;
- dispute -> деньги остаются замороженными до решения администратора.

## Frontend

Mini App и Admin должны быть тонкими клиентами. Нельзя переносить бизнес-логику денег, статусов и прав доступа во frontend.

Mini App должен поддерживать:

- первичный выбор роли;
- переключение рекламодатель/владелец;
- каталог каналов;
- создание заявки;
- баланс;
- заявки;
- споры;
- запрос вывода.

Admin должен поддерживать управление пользователями, каналами, категориями, форматами, заявками, модерацией, спорами, балансами, выплатами, рассылками и настройками.

## Bot

Bot отвечает за:

- `/start`;
- открытие Mini App;
- уведомления;
- проверку прав в канале;
- автопубликацию постов;
- системные рассылки с лимитами.

Bot не должен самостоятельно принимать финансовые решения. Он вызывает backend.

## Безопасность

- Проверять подпись Telegram Mini App init data.
- Хранить секреты только в переменных окружения.
- Защищать админ-панель отдельной авторизацией и ролями.
- Не логировать секреты, токены и персональные реквизиты выплат целиком.
- Для webhook и фоновых задач использовать идемпотентность.

## Что не входит в MVP

- автоматические выплаты через ЮKassa;
- полноценная юридическая верификация получателей выплат;
- сложные медиаформаты рекламных постов;
- рейтинги и отзывы;
- встроенный чат;
- ОРД/маркировка рекламы;
- мобильные приложения iOS/Android.
